# Day60 STT 작업 흐름 정리

## 1. STT 작업 생성



### ① 요청 데이터 검증

stt 진행을 위하여 파일과 spaceSeq와 kind를 입력하여 업로드를 진행후 stt작업을 진행

프론트엔드에서 전달받은 데이터가 올바른 형식인지 Pydantic으로 검사한다.

```python
class JobCreate(BaseModel):
    space_seq: int = Field(gt=0)  # 작업 공간 ID
    media_seq: int = Field(gt=0)  # 업로드된 미디어 ID

    # 허용된 작업 종류
    kind: Literal["stt", "audio-separation", "dubbing"]

    is_video_project: bool = False  # 영상 파일 여부
    title: str = Field(default="", max_length=150)
    source_language_code: str = "auto"  # 원본 언어
    target_language_code: str = "ko"
    tts_model: str = "LINNET_4"
    number_of_speakers: int = Field(default=1, ge=1, le=20)
    preferred_speed_type: Literal["GREEN", "RED"] = "GREEN"
    with_lip_sync: bool = False
    confirm_cost: bool = False  # 비용 발생 동의 여부
```

### ② STT 작업 생성


비용 동의 여부와 DB에 업로드된 미디어가 존재하는지 확인한 뒤 Perso API에 작업을 요청한다.

```python
async def create_job(req: JobCreate):
    # 실제 생성 비용 동의 확인
    if not req.confirm_cost:
        raise HTTPException(
            400,
            "실제 생성 비용 확인이 필요합니다 (confirm_cost=true)"
        )

    # DB에서 업로드한 미디어 확인
    asset = await repo.media_for_space(
        req.space_seq,
        req.media_seq
    )

    if asset is None:
        raise HTTPException(
            404,
            "현재 데이터베이스에 업로드한 mediaSeq가 없습니다"
        )

    # 업로드한 파일 유형과 요청한 프로젝트 유형 확인
    if (asset["kind"] == "video") != req.is_video_project:
        raise HTTPException(
            422,
            "업로드 미디어 유형과 is_video_project가 다릅니다"
        )

    if req.kind == "dubbing" and req.target_language_code == req.source_language_code:
        raise HTTPException(
            422,
            "원본 언어와 대상 언어를 다르게 설정하세요"
        )

    body = {
        "mediaSeq": req.media_seq,
        "isVideoProject": req.is_video_project
    }

    if req.title:
        body["title"] = req.title

    if req.kind == "dubbing":
        body.update({
            "sourceLanguageCode": req.source_language_code or "auto",
            "targetLanguages": [{
                "languageCode": req.target_language_code,
                "ttsModel": req.tts_model
            }],
            "numberOfSpeakers": req.number_of_speakers,
            "preferredSpeedType": req.preferred_speed_type,
            "withLipSync": req.with_lip_sync
        })

    # Perso API 작업 생성 요청
    client = PersoClient()
    await client.init_queue(req.space_seq)

    response = await client.start(
        req.space_seq,
        req.kind,
        body
    )

    # 생성된 프로젝트 번호 추출
    ids = project_ids(response)

    if not ids:
        raise HTTPException(
            502,
            "생성 응답에 projectSeq 목록이 없습니다. Perso 작업 내역을 확인하세요"
        )

    # 생성된 작업 정보를 DB에 저장
    await repo.save_jobs(
        req.space_seq,
        ids,
        req.kind,
        req.media_seq,
        req.title
    )

    await repo.audit(
        "JOB_CREATED",
        f"{req.kind} 프로젝트 생성 완료: {ids}",
        req.space_seq
    )

    return {
        "projectSeqList": ids,
        "spaceSeq": req.space_seq,
        "jobType": req.kind
    }
```

**핵심 내용**

- confirm_cost가 True인지 확인
- DB에 mediaSeq가 존재하는지 확인
- Perso API에 STT 작업 요청
- 반환된 projectSeq를 DB에 저장

### ③ 생성된 프로젝트 번호 저장


Perso API에서 발급한 projectSeq를 PostgreSQL의 perso_jobs 테이블에 저장한다.

```python
async def save_jobs(
    space_seq: int,
    project_seqs: list[int],
    job_type: str,
    media_seq: int | None,
    title: str,
    parent_project_seq: int | None = None
):
    async with db_connection() as conn:
        for project_seq in project_seqs:
            await conn.execute("""
                INSERT INTO perso_jobs
                (space_seq, project_seq, media_seq,
                 parent_project_seq, job_type, title)
                VALUES (%s, %s, %s, %s, %s, %s)
                ON CONFLICT (space_seq, project_seq) DO NOTHING
            """, (
                space_seq,
                project_seq,
                media_seq,
                parent_project_seq,
                job_type,
                title
            ))
```

## 2. 진행 상태 폴링

**작업 흐름**

Streamlit (5초마다) → FastAPI (/progress) → Perso API 진행 상태 조회 → PostgreSQL 갱신

STT는 비동기로 처리되므로 일정한 간격으로 작업 진행 상태를 확인한다.

### ① 프론트엔드 자동 조회


사용자가 자동 상태 조회 기능을 켜면 auto_poll이 True가 된다.

```python
st.toggle(
    "5초 간격 자동 상태 조회",
    key="auto_poll"
)

@st.fragment(run_every="5s" if auto_poll else None)
def progress_panel(...):
    # 진행 상태 조회
    api.get(
        f"/api/jobs/{space}/{project}/progress"
    )
```

- st.toggle: 자동 조회 기능 설정
- st.fragment: 특정 영역만 부분 재실행
- run_every="5s": 5초 간격으로 진행 상태 조회

### ② FastAPI GET 요청


실제 HTTP GET 요청을 보내는 공통 함수다.

```python
def get(path, **params):
    return request("GET", path, params=params)
```

### ③ 백엔드 진행 상태 조회


Perso API에서 현재 진행 상태를 가져오고 DB에 업데이트한다.

```python
async def refresh_progress(space_seq: int, project_seq: int):
    # DB에 해당 프로젝트가 있는지 확인
    job = await repo.get_job(space_seq, project_seq)

    if job is None:
        raise HTTPException(
            404,
            "해당 프로젝트가 DB에 없습니다"
        )

    # Perso API 진행 상태 조회
    try:
        response = await PersoClient().progress(
            space_seq,
            project_seq
        )
    except Exception as exc:
        await repo.mark_error(
            space_seq,
            project_seq,
            str(exc)
        )
        raise

    # 응답에서 상태와 진행률 추출
    root = result_data(response)

    if not isinstance(root, dict):
        root = {}

    status = str(
        root.get("progressReason")
        or root.get("status")
        or "Unknown"
    )

    progress = root.get("progress")

    try:
        progress = float(progress) if progress is not None else None
    except (TypeError, ValueError):
        progress = None

    # DB 진행 상태 업데이트
    await repo.update_status(
        space_seq,
        project_seq,
        status,
        progress,
        response
    )

    return {
        "spaceSeq": space_seq,
        "projectSeq": project_seq,
        "status": status,
        "progress": progress,
        "persoResponse": response
    }
```

### ④ DB 진행 상태 업데이트


Perso API에서 받은 진행 상태와 진행률을 DB에 저장한다.

```python
async def update_status(
    space_seq: int,
    project_seq: int,
    status: str,
    progress: float | None,
    raw: dict[str, Any]
):
    async with db_connection() as conn:
        await conn.execute("""
            UPDATE perso_jobs
            SET status=%s,
                progress=%s,
                result_json=%s,
                updated_at=NOW()
            WHERE space_seq=%s
              AND project_seq=%s
        """, (
            status,
            progress,
            Jsonb(raw),
            space_seq,
            project_seq
        ))
```

**핵심 내용**

- Streamlit에서 5초 간격으로 상태 조회
- Perso API에서 현재 진행률 확인
- 상태와 진행률을 PostgreSQL에 업데이트
- 조회 결과를 Streamlit 화면에 반환

## 3. STT 스크립트 결과 조회

**작업 흐름**

Streamlit → FastAPI (/script) → Perso API 스크립트 조회 → 전사 텍스트 출력

STT 작업이 완료되면 변환된 텍스트를 가져와 화면에 출력한다.

### ① 스크립트 조회 라우터


엔드포인트:

```text
GET /api/jobs/{space_seq}/{project_seq}/script
```

**처리 순서**

1. DB에서 해당 프로젝트의 작업 정보 확인
2. job_type이 스크립트 조회를 지원하는 작업인지 확인
3. PersoClient().script()로 외부 Perso API에 결과 요청
4. 조회한 스크립트 결과를 프론트엔드에 반환

실제 서비스 호출 형태:

```python
PersoClient().script(
    space_seq,
    project_seq,
    kind,
    cursor_id
)
```

### ② Streamlit 결과 출력


스크립트 응답의 sentences 배열에서 originalText를 추출해 하나의 텍스트로 연결한다.

```python
# 결과 탭에서 스크립트 조회
script = api.get(
    f"/api/jobs/{space}/{project}/script"
)

# sentences 배열에서 originalText 추출
sentences = script.get("sentences", [])

transcript = "\n".join(
    item.get("originalText", "")
    for item in sentences
)

# STT 전사 결과 화면 출력
st.text_area(
    "전사 텍스트",
    transcript
)
```

###  ③ 스크립트 Router (perso_router.py)
```python
@router.get("/jobs/{space_seq}/{project_seq}/script")
async def script(space_seq:int,project_seq:int,cursor_id:int|None=None):
    # DB(perso_jobs)에서 해당 space_seq와 project_seq에 일치하는 작업 레코드를 조회
    job=await repo.get_job(space_seq,project_seq)
    
    # 작업 기록이 없으면 외부 API 호출 전에 HTTP 404 에러
    if not job:raise HTTPException(404,"DB에서 작업을 찾을 수 없습니다")
    
    # DB(perso_jobs)에서 작업 종류(job_type: stt, audio-separation, dubbing 등) 추출
    kind=job["job_type"]
    # 스크립트를 지원하는 작업 유형이 아니면 HTTP 422 에러 반환
    if kind not in ("stt","audio-separation","dubbing"):
        raise HTTPException(422,"해당 작업은 스크립트를 지원하지 않습니다")
    
    # PersoClient를 통해 작업 종류(kind)와 cursor_id에 맞는 Perso 스크립트 API 호출 후 결과 반환
    try:
        return await PersoClient().script(space_seq,project_seq,kind,cursor_id)
    # PersoError 발생 시 api_error()로 HTTPException(4xx 유지, 5xx는 502 변환)으로 바꿈
    except PersoError as exc:raise api_error(exc) from exc


```

###  ④ 실제 Perso 외부 API에 스크립트를 요청하는 부분  (perso_client.py)
```python
# 작업 종류(kind)와 페이지네이션 커서(cursor_id)로 Perso 스크립트 API 조회
async def script(self,space_seq:int,project_seq:int,kind:str,cursor_id:int|None=None):
    # 작업 종류별 하위 경로 매핑 ("stt":"stt/script")
    sub={"stt":"stt/script","audio-separation":"audio-separation/script","dubbing":"script"}[kind]
    # 한 번에 가져올 최대 항목 수 설정
    params={"size":100}
    # 커서가 있으면 다음 페이지 조회용 파라미터 추가
    if cursor_id is not None:params["cursorId"]=cursor_id
    # GET 요청(재시도 정책 적용)
    return await self.call("GET",f"{PREFIX}/projects/{project_seq}/spaces/{space_seq}/{sub}",params=params)

```

**핵심 내용**

- 완료된 STT 프로젝트의 스크립트 조회
- sentences 배열에서 originalText 추출
- 추출한 문장을 연결
- Streamlit 화면에 최종 전사 텍스트 출력

## 4. 핵심 용어 정리

| 용어 | 의미 |
|---|---|
| spaceSeq | 작업 공간 번호 |
| mediaSeq | 업로드한 원본 파일 번호 |
| projectSeq | 생성된 STT 작업 번호 |
| JobCreate | 요청 데이터 검증 모델 |
| PersoClient | 외부 Perso API 통신 클래스 |
| create_job | STT 작업 생성 함수 |
| refresh_progress | 작업 진행 상태 조회 함수 |
| save_jobs | 생성된 프로젝트 번호 DB 저장 함수 |
| update_status | 진행 상태 DB 업데이트 함수 |
| polling | 일정한 간격으로 진행 상태를 반복 조회하는 방식 |
| originalText | STT로 변환된 문장 텍스트 |

## 5. 최종 정리

Day60의 STT 기능은 다음 세 단계로 구성된다.

1. **STT 작업 생성:** 요청 데이터를 검증하고 Perso API에 작업을 요청한 뒤 projectSeq를 DB에 저장한다.
2. **진행 상태 폴링:** Streamlit에서 5초마다 작업 상태를 조회하고 PostgreSQL을 갱신한다.
3. **스크립트 조회:** STT 변환 결과에서 originalText를 추출해 Streamlit 화면에 출력한다.

즉, Streamlit은 사용자 화면, FastAPI는 요청 처리, Perso API는 실제 STT 작업, PostgreSQL은 작업 정보와 진행 상태 저장을 담당한다.
